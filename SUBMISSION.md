# MergeZero submission notes

## Category

Standalone GenLayer Intelligent Contract / reusable primitive. No frontend.

## One-line purpose

MergeZero lets independent actors safely combine structurally disjoint concurrent
state patches only when GenLayer validators independently agree that the two
frozen changes semantically commute.

## Why GenLayer is necessary

A deterministic merge engine can detect path collisions but cannot generally
decide whether two changes on different fields undermine each other in meaning.
MergeZero confines GenLayer consensus to that semantic pair judgement while
keeping all state construction deterministic.

## Consensus design

Leader output is bounded to:

```json
{"verdict":"COMMUTE|CONFLICT|AMBIGUOUS","reason":"..."}
```

Validators independently re-run the semantic pair classification. Exact reason
text is diagnostic; the consensus-critical verdict must match. An unrecognised
verdict normalises to `AMBIGUOUS`, so a leader cannot smuggle a merge through by
inventing a token.

`COMMUTE` is not sufficient on its own: deterministic checks must already prove
common base, matching operation pre-image hashes, disjoint paths, and
byte-identical A→B / B→A application.

The `gl.nondet.exec_prompt` call is placed directly inside both `leader_fn` and
`validator_fn` (no shared helper function), so the GenVM equivalence-principle
linter can statically confirm that the nondeterministic call is reachable from
both execution paths.

## Deterministic state design

The model never writes the merged state. A successful version is recomputed
entirely from the two sealed operation lists; any extra field the model returns
is discarded. Conflict and ambiguity produce no version, and a pair's first
resolution is final, so a rejected pair cannot be re-rolled into a merge.

### 1. Structurally disjoint, semantically conflicting — no version created

`merge_patches(1, 2)` — tx `0x7e96271bb4d8d85c60c06df154e2627e00edd1aa8137ac416839ec0d7169039f`

Patch 1 set `/auth/password_login` to `false` ("Disable password authentication
for ordinary access"). Patch 2 set `/recovery/password_recovery` to `true`
("Keep password recovery as the required ordinary recovery mechanism"). The two
JSON paths are structurally disjoint, so an ordinary structural merge would have
accepted the pair.

Receipt 1: `status_name = SEMANTIC_CONFLICT`, `merged_version_id = 0`,
`merged_state_hash = ""`. `next_version_id` was unchanged across the call, and
`is_safe_merge` is false for this receipt.

Validators' recorded reason (diagnostic only — it does not affect state):

> Patch A disables password authentication for ordinary access, while Patch B
> explicitly relies on password recovery as the required ordinary recovery
> mechanism. These intents are semantically contradictory: disabling password
> authentication undermines the ability to use password recovery, making Patch B's
> intent unsafe and incoherent under the workspace scope's requirement for coherent
> authentication and recovery policies.

### 2. Genuinely commuting pair — exact deterministic version created

`merge_patches(3, 4)` — tx `0x0d3a6e8b3f8934d384ef9b1dbadaa8b9859f48b97ccb571eafe3e7a7fe4cbf4a`

Receipt 2: `status_name = COMMUTE`, `merged_version_id = 6`.

Merged state (version 6), byte-for-byte as stored on chain:

```json
{"auth":{"mfa_required":false,"password_login":true},"limits":{"daily":1500},"notifications":{"email":"platform@example.com"},"recovery":{"admin_breakglass":false,"password_recovery":true}}
```

`merged_state_hash = e8294265ef15dca31aed071b3a7d71e68ca8fbe170f5c9860a8cba5bff90f9fb`

That is exactly Keccak-256 of those bytes, and those bytes are exactly the base
state with the two sealed operations applied. Both are reproducible off-chain
without touching the network:

```python
import json
from eth_utils import keccak

state = {
    "auth": {"password_login": True, "mfa_required": False},
    "recovery": {"password_recovery": True, "admin_breakglass": False},
    "notifications": {"email": "ops@example.com"},
    "limits": {"daily": 1000},
}
state["notifications"]["email"] = "platform@example.com"   # patch 3
state["limits"]["daily"] = 1500                            # patch 4
canonical = json.dumps(state, sort_keys=True, separators=(",", ":"), ensure_ascii=True)
assert keccak(text=canonical).hex() == "e8294265ef15dca31aed071b3a7d71e68ca8fbe170f5c9860a8cba5bff90f9fb"
```

## Limitations a reviewer should know

- The `genlayer` Node CLI at `0.40.0-rc.3` cannot deploy to the current hosted
  Studio: `estimate-fees` fails with `Method not found: sim_getFeeConfig`, and
  `deploy` produces a transaction that finalizes as `NO_MAJORITY` with
  `activator: ''` and zero votes committed. This was confirmed to be a client
  issue by reproducing it with a fifteen-line no-op contract. All deployment
  here goes through `genlayer-py`, which reaches `MAJORITY_AGREE` normally.
- The hosted Studio intermittently returns database connection-pool errors.
  `tests/integration/conftest.py` retries those specific transport errors and
  nothing else; contract-level errors are never retried.
- `merge_patches` is permissionless, and a pair's first resolution is final.
  That combination is deliberate — it prevents verdict grinding — but it means a
  third party can settle a pair before its authors do.
- Semantic classification depends on the workspace scope and patch intents being
  descriptive. MergeZero does not judge either patch in isolation, does not do
  three-way text merging, and never auto-resolves a conflict.
- Path traversal addresses object keys only; arrays are supported as values but
  are not addressable element-by-element.
